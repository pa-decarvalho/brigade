Recipes¶

Tested dishes: a whole project, from the first commit to its release.

Each recipe is a real project that brigade's tests build and run end to end (ctt.toml): pick the same tools to get the same kitchen.

Python package¶

A library with its tests and docs, released by Releasaurus and published to PyPI (or another index) on each tag. Tested as the python-github variant.

uv init --lib my-package
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade my-package

Tick the python and docs presets, then add the rest in tools. In .brigade/copier/data.yml:

ci: "github"
uv_publish: true
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "taplo"
  - "rumdl"
  - "ruff"
  - "ty"
  - "osv-scanner"
  - "pytest"
  - "uv"
  - "zensical"
  - "pages"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, TOML, Markdown, spelling, .editorconfig, secrets, workflows (zizmor), Python (ruff, ty), vulnerable dependencies in uv.lock (osv-scanner)
build the package (uv build) and the docs site (zensical)
test pytest
release the release PR, then the tag (releasaurus)
deploy the docs to GitHub Pages (pages), the package to PyPI (uv, with uv_publish: true)
operate dependency updates (renovate)

Your part: the code in src/, the tests in tests/, the docs in docs/ with a zensical.toml, an .editorconfig, and these secrets: UV_PUBLISH_TOKEN (a PyPI token; another index: UV_PUBLISH_URL), RENOVATE_TOKEN, and optionally RELEASAURUS_GITHUB_TOKEN (see release). In Settings → Pages, deploy from the gh-pages branch.

The test publishes to a local PyPI (pypiserver in Docker) twice: the second run skips the files already there.

Go command¶

A command with its tests, released by Releasaurus, its binaries for Linux, macOS and Windows attached to each release by GoReleaser. Tested as the go-github variant (GoReleaser in snapshot mode: it builds every archive without publishing).

mkdir my-command && cd my-command && git init
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade .
mise exec -- go mod init example.com/my-command

In .brigade/copier/data.yml:

ci: "github"
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "golangci-lint"
  - "revive"
  - "osv-scanner"
  - "go"
  - "goreleaser"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, spelling, .editorconfig, secrets, workflows (zizmor), Go (golangci-lint, revive), vulnerable modules (osv-scanner)
build go build ./... (Go installed by the go tool)
test go test ./...
release the release PR, then the tag (releasaurus)
deploy the binaries and their checksums attached to the release (goreleaser)
operate dependency updates (renovate)

Your part: the Go code and its tests, a .gitignore with dist/ and the binary go build writes, an .editorconfig, and the secrets RENOVATE_TOKEN and optionally RELEASAURUS_GITHUB_TOKEN (see release). GoReleaser uses the workflow token; its settings are in .brigade/configs/goreleaser.yaml.

Docker image¶

An image with its structure tests, released by Releasaurus and pushed to a registry on each release (ghcr.io on GitHub). Tested through the Python app in Docker variant, which builds, checks and pushes its image the same way.

mkdir my-image && cd my-image && git init
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade .

In .brigade/copier/data.yml:

ci: "github"
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "hadolint"
  - "trivy"
  - "checkov"
  - "docker"
  - "container-structure-test"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, spelling, .editorconfig, secrets, workflows (zizmor), the Dockerfile (hadolint, checkov), vulnerable dependencies and secrets (trivy)
build docker build .
test the image's content (container-structure-test)
release the release PR, then the tag (releasaurus)
deploy the image, tagged X.Y.Z and latest, pushed to ghcr.io/<owner>/<repo> (docker)
operate dependency updates, the FROM images included (renovate)

Your part: the Dockerfile, your image's tests in .brigade/configs/container-structure-test.yaml (brigade writes a placeholder), an .editorconfig, and the secrets RENOVATE_TOKEN and optionally RELEASAURUS_GITHUB_TOKEN (see release). Another registry: DOCKER_IMAGE, DOCKER_USERNAME and DOCKER_PASSWORD (see deploy).

Python app in Docker¶

An application shipped as a Docker image: tested as code (pytest) and as an image (container-structure-test), pushed to a registry on each release, not published to PyPI. Tested as the python-docker-github variant, which pushes to a local registry in Docker.

uv init --package my-app
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade my-app

In .brigade/copier/data.yml:

ci: "github"
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "ruff"
  - "ty"
  - "osv-scanner"
  - "hadolint"
  - "checkov"
  - "pytest"
  - "docker"
  - "container-structure-test"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, spelling, .editorconfig, secrets, workflows (zizmor), Python (ruff, ty), vulnerable dependencies in uv.lock (osv-scanner), the Dockerfile (hadolint, checkov)
build docker build .
test pytest, the image's content (container-structure-test)
release the release PR (it bumps pyproject.toml), then the tag (releasaurus)
deploy the image, tagged X.Y.Z and latest, pushed to ghcr.io/<owner>/<repo> (docker)
operate dependency updates, uv.lock and the FROM image included (renovate)

No uv tool: it builds a package (uv build), which an app does not need; the Dockerfile installs the app. A Dockerfile from uv's image:

FROM ghcr.io/astral-sh/uv:0.13.8-python3.14-trixie-slim
WORKDIR /app
ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_NO_CACHE=1
COPY pyproject.toml uv.lock README.md ./
COPY src ./src
RUN uv sync --frozen --no-dev
USER 65534
HEALTHCHECK NONE
ENTRYPOINT ["/app/.venv/bin/my-app"]

Your part: the code in src/, the tests in tests/, the Dockerfile and a .dockerignore (at least .git, .venv, .mise-data: a local .venv must not end up in the image), your image's tests in .brigade/configs/container-structure-test.yaml, an .editorconfig, and the secrets RENOVATE_TOKEN and optionally RELEASAURUS_GITHUB_TOKEN.

TypeScript library¶

A library with its tests, released by Releasaurus and published to npm on each release. JavaScript works the same: the node tool runs your package.json scripts, and a missing build script does nothing. Tested as the node-github variant, which publishes to a local npm registry (Verdaccio in Docker).

mkdir my-lib && cd my-lib && git init && npm init -y
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade .

In .brigade/copier/data.yml:

ci: "github"
npm_publish: true
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "biome"
  - "osv-scanner"
  - "node"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, spelling, .editorconfig, secrets, workflows (zizmor), TypeScript and JSON (biome: lint and formatting), vulnerable dependencies in package-lock.json (osv-scanner)
build npm ci, then your build script (tsc; Node.js installed by the node tool)
test npm ci, then your test script (node --test: Node runs .ts files)
release the release PR (it bumps package.json), then the tag (releasaurus)
deploy the package to npm (node, with npm_publish: true)
operate dependency updates, package-lock.json included (renovate)

The scripts in package.json:

"scripts": {
    "build": "tsc",
    "test": "node --test",
    "prepublishOnly": "npm run build"
}

Your part: the code in src/, the tests, package.json with its scripts and a committed package-lock.json, a tsconfig.json, a .gitignore with node_modules/ and dist/, an .editorconfig, the line //registry.npmjs.org/:_authToken=${NPM_TOKEN} in .npmrc, and the secrets NPM_TOKEN, RENOVATE_TOKEN and optionally RELEASAURUS_GITHUB_TOKEN.

React app¶

A Vite React app in TypeScript, linted by ESLint, tested by Vitest, published to GitHub Pages on each release. Tested as the react-github variant.

npm create vite@latest my-app -- --template react-ts
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade my-app

In .brigade/copier/data.yml:

ci: "github"
pages_dir: "dist"
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "node"
  - "pages"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, spelling, .editorconfig, secrets, workflows (zizmor), your lint script (eslint ., with its plugins as dependencies)
build npm ci, then your build script (tsc && vite build, into dist/)
test npm ci, then your test script
release the release PR, then the tag (releasaurus)
deploy dist/ to GitHub Pages (pages, with pages_dir: dist)
operate dependency updates, package-lock.json included (renovate)

Your test script must run once and exit: "test": "vitest run" (vitest alone watches the files and waits, except in CI). A Pages site at https://<owner>.github.io/<repo>/ needs Vite's base: "/<repo>/". Shipping the app as an image (nginx serving dist/) instead: the docker tool, as in Docker image.

osv-scanner checks package-lock.json too; with many dependencies, expect a new advisory to fail an unchanged project until Renovate or you update the package.

Angular app¶

An Angular app, unit-tested by Vitest, tested end to end by CodeceptJS (Chromium, through Playwright), published to GitHub Pages on each release. Tested as the angular-github variant. Examples: on GitHub (site) and on GitLab (ci: gitlab, site).

npx @angular/cli new my-app --defaults
uvx copier@9.19.1 copy gh:pa-decarvalho/brigade my-app
cd my-app
npm install -D codeceptjs playwright
npx codeceptjs init

In .brigade/copier/data.yml:

ci: "github"
pages_dir: "dist/my-app/browser"
tools:
  - "brigade"
  - "yamllint"
  - "gitleaks"
  - "typos"
  - "editorconfig-checker"
  - "zizmor"
  - "node"
  - "codeceptjs"
  - "pages"
  - "releasaurus"
  - "renovate"
Stage What runs
lint brigade, YAML, spelling, .editorconfig, secrets, workflows (zizmor), your lint script if any (ng lint, with angular-eslint)
build npm ci, then your build script (ng build, into dist/my-app/browser/)
test npm ci, your test script (ng test, Vitest), then CodeceptJS against the app in Chromium (codeceptjs)
release the release PR, then the tag (releasaurus)
deploy dist/my-app/browser/ to GitHub Pages (pages, with pages_dir)
operate dependency updates, package-lock.json included (renovate)

Your test script must run once and exit: "test": "ng test --watch=false". CodeceptJS tests the app while it runs: its bootstrap builds it and serves dist/my-app/browser/ (the test job does not have the build stage's output), its teardown stops the server; see the angular-github variant in brigade's ctt.toml for a codecept.conf.js that does it with Node's http module. A Pages site at https://<owner>.github.io/<repo>/ needs "baseHref": "/<repo>/" in angular.json (GitLab's unique domain: none, see deploy). The Angular CLI is a dependency of the project, installed by npm ci.
