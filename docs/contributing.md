# Contributing

*Back of house: something burned, a tool missing from the station, or a hand in
the kitchen.*

## Issues

[Open an issue](https://github.com/pa-decarvalho/brigade/issues/new/choose) with
one of the forms:

- **🔥 Something burned**: a task, a generated file or the CI does not work as
  documented. Give your brigade version (`_commit` in
  `.brigade/copier/answers.yml`), the command and its full output, and your
  `.brigade/copier/data.yml`: with it, the same project can be generated to
  reproduce the bug. Try `mise run brigade:update` first: it may already be
  fixed.
- **🔪 New tool for the station**: a tool for the [catalog](tools.md). It must
  install with mise and run on its own; tools already planned are listed in
  [#138](https://github.com/pa-decarvalho/brigade/issues/138).
- **🧑‍🍳 New recipe**: any other idea. Start with the need, then the idea.

Search the
[existing issues](https://github.com/pa-decarvalho/brigade/issues?q=is%3Aissue)
first, and never paste a secret or token.

## Development

Working on brigade itself. Requires [mise](https://mise.jdx.dev/) and a running
Docker (the Docker, Ansible and publishing variants use it).

```sh
mise install
mise run lint
mise run build            # the documentation site, strict
mise run test
mise run zensical:serve   # preview the site
```

PRs are squash-merged with their title as commit message: the pull request
template (`.github/pull_request_template.md`) lists what to check before opening
one.

### Repository

- `copier.yml` includes `.copier/settings.yml` and `.copier/questions/`:
  `common.yml`, then one file per tool in `tools/`.
- `template/` holds the generated files.
- `ctt.toml` lists the test variants.
- `docs/` and `zensical.toml` hold this site.

brigade is generated by brigade: `.miserc.toml`, `.brigade/` and the
`.github/workflows/` files come from the latest release, with the answers in
`.brigade/copier/data.yml` (taplo's file list, `ctt:test` clearing `.ctt/`
first, the Renovate config path), and the lint settings skipping `template/` and
`.ctt/` in `.brigade/configs/`. `mise run brigade:update` updates them after a
release. brigade's own settings (the `.ctt/` env, the `forges:*` tasks) live in
`mise.toml`: brigade is tested with the tools it ships, except the end-to-end
tests on local forges (`tests/e2e/`, see below).

### Lint

`mise run lint` checks this repo: yamllint, jactionlint, zizmor (brigade's own
workflows and actions), taplo, editorconfig-checker, gitleaks, typos, ruff and
ty (the scripts), rumdl (Markdown), lychee (links, external ones included: it
needs the network), ls-lint (names) and the Renovate config schema.

### Tests

`mise run test` runs `ctt:test`:
[ctt](https://github.com/KyleKing/copier-template-tester) renders each
`ctt.toml` variant into `.ctt/`, creates a real project there with the
ecosystem's tool, then runs its stages. The variants do not replay their
generated CI (act, gitlab-ci-local): it ran their stages a second time; the CI
files are still linted (jactionlint, gitlab-ci). See #211 for running them
again. ctt only sees files tracked by git: `git add` new template files before
testing.

brigade's CI runs these tests on Linux only.

### Local forges

`mise run forges:test -- --forge <forge>` runs brigade end to end on a local
forge with its runner (Docker Compose, local only): `gitea`, `forgejo`,
`gitlab`, or `github` (a `ci: github` project on Gitea, whose runner runs GitHub
Actions workflows). pytest runs on this machine, one test per project type of
`tests/e2e/projects.py` (`python`, `node`, `docker`; `-k <type>` for one), each
in a temporary folder:

1. the project, created with its ecosystem's tool, brigade applied from this
   checkout at its latest tag;
2. its settings (secrets, `<cli>:setup` and `<cli>:check`), then the push;
3. a pull request: lint, build, test;
4. its merge: the release PR, then the `X.Y.Z` tag (not on `github`: GitHub's
   API);
5. the deploy, to a local registry (`tests/fixtures/compose.yml`);
6. `brigade:update` to this checkout's `HEAD`, in a pull request whose CI
   passes.

The checkout is the projects' `_src_path`, mounted at the same path in the
jobs, uncommitted changes included. The forge starts on first use
(`tests/e2e/up.py`; GitLab needs about 4 GB of RAM, a few minutes, and a TLS
proxy since Releasaurus only calls GitLab over HTTPS, #301) and stays up for
the next runs: `mise run forges:up -- <forge>` prints its URL and login, `mise
run forges:down` removes them with their data, then everything Docker no longer
uses, Docker-wide (`docker system prune --all --volumes`: stopped containers,
unused images, anonymous volumes; images are pulled again when needed). Each
test writes a note in `.forges/`: every step's result and time, the failed
jobs' last log lines, and a "To improve" section to turn into issues.

`mise run build` builds this site in strict mode, which fails on broken links.
CI deploys it (`pages:deploy`, to the `gh-pages` branch) on each release tag and
on a manual run of the Deploy workflow.

### Versions and releases

Pinned versions are updated by [Renovate](https://docs.renovatebot.com/)
(`.brigade/configs/renovate.json`, generated with `renovate_updates: [brigade,
template]` and `renovate_automerge: true` in `.brigade/copier/data.yml`), run
every day by the generated Operate workflow
(`mise run operate`, `operate_schedule`) as one PR,
`fix(deps): update template`, major updates included: it triggers a release.

Renovate only reads `template/`. brigade's generated files get the new versions
like any project, through a release and `mise run brigade:update`; its other
pins (Copier and pytest in `ctt.toml`, `README.md` and `.copier/settings.yml`)
are updated by hand.

It needs a `RENOVATE_TOKEN` secret: a fine-grained token on this repo with
contents, pull requests, issues, workflows and commit statuses read/write.

Commits and PR titles follow Conventional Commits. On each push to `main`, the
CI's `release` job runs
[Releasaurus](https://github.com/robgonnella/releasaurus) (`mise run release`):
it opens or updates the release PR, and once merged tags `X.Y.Z` and updates
`CHANGELOG.md`; Copier uses these tags as template versions. `releasaurus.toml`
makes a release on `feat`, `fix`, `perf`, `revert` and breaking changes only:
other commits do not change the template.

It uses the `RELEASAURUS_GITHUB_TOKEN` secret, a fine-grained token on this repo
with contents, issues and pull requests read/write: unlike the workflow token,
its release PR runs the checks and its tag starts the Deploy workflow.
